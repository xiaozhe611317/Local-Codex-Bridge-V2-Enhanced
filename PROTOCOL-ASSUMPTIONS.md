# Native Codex App-Server Protocol Assumptions

**Status:** V2.1.3 maintenance baseline, derived from the accepted Bridge implementation and the established stable upstream contracts used for this maintenance round. Revalidate this checklist whenever the native Codex runtime is upgraded. This is an upgrade aid, not a complete app-server protocol reference.

LCB remains a thin supervisory MCP adapter. The native Codex thread/session is the sole execution source of truth; Bridge state must not become a second task system, model-state registry, or lifecycle authority.

## Revalidation triggers

Revisit this checklist when:

- the official Codex executable or app-server protocol is upgraded;
- any listed method changes request, response, pagination, id, scope, or timeout semantics;
- a required-envelope or protocol-identity check begins failing against native Codex;
- the related model, response, timeout, duplicate-id, or version-anchor tests change or fail;
- Bridge proposes support for a currently deliberate non-assumption.

## Deliberate non-assumptions

- No `serviceTier` or provider-capability abstraction.
- No current-model registry, model cache, or model-state reconstruction from `thread/read`.
- No dependency on `command/exec`, `thread/turns/list`, or `sourceKinds`.
- No elicitation response support.
- No queued-message facade; `turn/steer` remains a semantic correction to one active turn.
- No new late-response telemetry contract or public surface was added by the V2.1.3 maintenance round.

## Isolated development extensions (2.1.3 version retained; not a release)

- `bridge_status` reports only running process constants/counters and a build-time compiled-JS fingerprint. No Git/config/environment value is treated as loaded-build identity. Missing identity/PID is explicitly unavailable. A fingerprint is not an authenticity guarantee.
- `codex_runtime.status` inspects only the managed child and Bridge-owned live/in-flight state, without spawning. `restart` synchronously excludes active turns, all pending server requests, full turn transactions, outstanding RPCs/writes, initialization/close/restart, and live-child UNKNOWN mutations. UNKNOWN conservatively survives retention expiry; only a valid scoped late acknowledgement may settle a retained request. A process exit allows explicit recovery; ordinary calls still never auto-restart.
- Restart confirms the old managed child's exit and repeats the same initialize/initialized handshake. Old callbacks cannot populate a new child generation. It clears live data, wakes observers, publishes zero UX counts, and advances a cursor floor for subsequent live threads. Persisted-history fallback retains its explicitly degraded cursor semantics; it does not reconstruct old live events. No native threads or checkpoints are erased.
- Supervision is a projection of an already-consumed raw page. Only exact known agent delta/tokenUsage notification names are suppressed. Requests/unknown methods remain visible. All cursor, cursor_lost and has_more values come from the raw page, including pages with zero visible events. Suppression summaries are per consumed page, bounded by limit; no counts are invented for ring loss. Wait/cancel behavior remains the raw observer's event-driven contract.
- `context_verification.native_thread_context` uses only top-level thread/start/resume response fields cwd, sandbox, approvalPolicy, model and reasoningEffort. Each field carries an exact source and a before-turn scope. Missing/unusable evidence is unknown. `turn/start` has no supported authoritative context readback, so accepted-turn effective fields remain verified:false even when requested values match earlier thread settings. Never infer them from request echo, model/list, or persisted thread model fields.
- Optional targeting policy is read once through an explicit absolute `LOCAL_CODEX_BRIDGE_LOCAL_SETTINGS_FILE`; only the targeting member of existing local settings is consumed. No implicit home search, model state or permission override is created. Its closed schema accepts allowed_roots and string-only project_aliases; aliases and cwd conflict.
- With roots enabled, inherited resume cwd requires a scoped thread/read before resume (preserving cwd omission), followed by scoped top-level effective cwd evidence from thread/resume. Fresh/explicit/alias targets also require filesystem checks before mutation and effective readback before turn/start. Missing evidence fails closed; a failed readback may leave a created/resumed native thread but starts no turn. Unconfigured behavior remains unchanged.
- Windows targeting rejects traversal and ambiguous path forms, uses component boundaries and native realpath/stat plus ancestor directory identity, and conservatively refuses linked ancestors/roots (including junctions). Failure to canonicalize denies targeting. This is not an OS sandbox/ACL and cannot prevent later filesystem races or commands accessing paths using native capabilities. macOS uses case-sensitive POSIX semantics; actual macOS platform integration still requires validation on macOS.

Evidence: `test/enhancements.test.ts`, `test/targeting.test.ts`, `test/runtime-codex.mjs`, `test/tool-contract.test.ts`, and the existing MCP/platform/Tray suites. Native behavior is tested with fakes; no live Codex session was used to infer new protocol support.

## Default auto transport and manual compatibility

- Ordinary observe now defaults to auto without an explicit cursor. This is the explicitly requested default change; manual cursor calls preserve native/raw pagination, pending/terminal snapshots and degraded persisted-history fallback. Explicit supervision suppresses noise without diagnostic raw expansion; explicit raw is debugging/evidence. All modes without a cursor use the same per-connection/thread incremental cursor; manual reads neither inspect nor advance it.
- Connection cursors are bounded delivery metadata (128 threads, 128 pending references per thread). They contain no transcript, current-model state or jobs. MCP writes commit them only after successful, uncancelled result delivery. Cancellation/write failure rolls back. Same-connection/thread concurrent automatic calls fail explicitly; no queue is created. Connection close or generation loss cannot fabricate prior consumption.
- Main events are only the consumed delta. Normal auto/supervision removes embedded turn/completed items and terminal.turn history, and references already-delivered identical final text; explicit raw keeps that evidence. Automatic pending/terminal payloads are changes; current counts and terminal_unchanged avoid pretending a missing delta is absent state. Manual reads retain snapshots. All raw ring cursor/floor/has_more semantics and bounded suppression accounting remain unchanged by filtering.
- Auto diagnostics are driven by actual runtime/connection evidence: cursor loss, UNKNOWN mutation, unexpected exit/unavailability, restart failure, protocol/JSON-RPC errors, unknown pending/state, turn/terminal conflict, and nonzero native command exit with absent/truncated summary detail. A valid scoped late acknowledgement may settle UNKNOWN; expired/malformed/mismatched evidence cannot. An unread error disappearing from the delta never proves native recovery.
- Diagnostic expansion is related, bounded recent evidence, never a history replay: at most six event excerpts and 6000 serialized characters, four runtime records and four connection error responses. Diagnostic excerpts do not advance the event cursor. Persistent unchanged anomalies do not repeat old raw excerpts. Runtime and connection diagnostic rings are bounded at 32 records each.
- delta_summary always has changes/commands/validation/pending/unresolved/next (arrays, at most eight entries each). Every item derives from native events, pending transitions or explicit transport state. Reported command exit codes are evidence, not a test-suite or task acceptance verdict. No language-model summarization, guessing or new execution authority is involved.
- cursor_lost, generation/connection cursor loss, and unavailable live history require explicit supervisor re-anchoring. Auto reports unreconstructable live state with unavailable/null live cursors, without reading/replaying persistent turns; manual evidence reads remain available. Optional checkpoint stays a concise persistent supervisor snapshot of goal/constraints/current state/validation/unresolved, never a chat or log mirror.
- GPT supervises; Bridge transports, controls and provides evidence; native Codex executes. These defaults and descriptions are shipped in the tool contract, not an external prompt recipe. Still exactly ten tools; no Goal passthrough or second agent/job runtime.

Evidence: test/auto-observe.test.ts, test/auto-mcp-fixture.mjs and the independent MCP stdio test, plus real fake-child UNKNOWN/late-response/error/restart tests.

A turn/completed notification for a different turn preserves the exact known active turn and its pending requests; Bridge records the contradictory scoped event and requires re-anchoring instead of declaring the active turn complete.

## Audit blocker corrections

- Restart also denies any unrecognized native runtime/thread status with the single bounded reason `unknown_runtime_state` and a count, without returning raw status values. Malformed status notifications become unknown instead of retaining a formerly safe idle status. Known subsequent native state evidence can settle that condition; existing active, pending and UNKNOWN mutation guards remain independent.
- Automatic observation leases reserve bounded capacity separately from successfully delivered cursors. Eviction makes the cursor unavailable; rollback/cancellation/write failure cannot replace that absence with a fabricated initial cursor. Retained events returned during re-anchoring remain explicitly marked as unanchored, never silently presented as a known unseen delta. Only successful delivery commits the cursor and LRU position.

Regression evidence: unknown-state runtime tool denial/recovery, ControlSurface eviction plus repeated deferred rollback, real MCP stdout failure after eviction, and reserved-capacity enforcement.

A late `turn/start` success acknowledgement must contain a scoped turn ID and a supported native Turn status (`inProgress`, `completed`, `failed`, or `interrupted`) before it can reconcile state or settle UNKNOWN. Missing, malformed, unknown or unsupported statuses retain the unresolved mutation and its bounded restart denial, even if the existing Bridge snapshot is idle or terminal. Thread/Bridge status values such as `idle` do not establish a native Turn status. Invalid evidence does not create a successful reconciliation event or replace prior runtime evidence; actual managed-child exit still permits controlled explicit recovery. Fake-child regressions exercise timeout, late-ack delivery, runtime tool refusal, earlier terminal preservation, recognized statuses and exit/restart handshake recovery.
